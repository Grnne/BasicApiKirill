# Архитектура бэкенда

Приватный мессенджер для команд и сообществ, который организация разворачивает у себя
(self-hosted, одна установка — одна организация). Один docker-compose: API, Postgres,
S3-совместимое хранилище файлов, Caddy. Ориентиры: по функциям — Element, Wire, Mattermost,
по UX — Telegram.

Стек: .NET 10, ASP.NET Core (REST + SignalR), Dapper поверх Postgres, FluentMigrator (миграции
на старте), JWT + серверные сессии, WebPush. Фронт — Vue SPA в `BasicWebClient`, отдаётся тем же
сервером.

---

## Карта решения

```
BasicApi/                  веб-приложение
  Features/<Функция>/      контроллер, сервисы, DTO запросов и регистрация одной функции
  Services/                общее для нескольких функций: права, присутствие, мапперы
    Events/                outbox, журнал, публикаторы событий, очередь push
  Models/                  общие DTO: сообщение, карточка чата, полезные нагрузки событий
  Hubs/                    SignalR-хаб, реестр соединений, монитор сессий
  Middleware/              ошибки → ProblemDetails; исключения предметной области
  Extensions/              корень композиции: хранилище, общие сервисы, auth, лимиты, Swagger
  Program.cs               конвейер запроса
BasicApi.Storage/          сущности, репозитории (Dapper + SQL), миграции
BasicApi.Tests/            юнит-тесты: Features/<Функция>, Services, Hubs, Middleware, Extensions
BasicApi.IntegrationTests/ тесты на реальном Postgres и S3 в контейнерах:
                           Features/<Функция>, Platform (сквозное), Migrations, Repositories, E2E
tools/BasicApi.LoadTest/   нагрузочный прогон
BasicWebClient/            веб-клиент: Vue 3 + TypeScript + Pinia, тесты — Vitest
```

Функции: **Auth** (вход, сессии, токены), **Devices** (входы пользователя), **Push**,
**Chats** (список, личные, «Избранное», закреп/архив/mute, карточка, поиск чатов),
**Messages** (история, отправка, пересылка, правка, удаление, реакции, черновики, «печатает»,
прочтение, галерея, поиск), **Groups**, **Folders**, **Media**, **Users** (профиль,
приватность, блокировки, поиск людей), **Sync** (журнал и снимок состояния), **Config** (лимиты
и переключатели экземпляра для клиентов).

Namespace совпадает с папкой. DTO запросов функции лежат в её папке плоско, общие — в
`Models/Dto/<Область>`. Каждая функция регистрирует свои сервисы в
`Features/<Функция>/<Функция>Feature.cs` (`AddXxxFeature()`).

## Правила зависимостей

| Кто | Может зависеть от | Не может |
|---|---|---|
| Функция `Features/X` | `Services/`, `Models/`, `BasicApi.Storage`, `Hubs/`; другой функции — только из списка ниже | внутренних классов других функций |
| Общее `Services/`, `Models/` | друг от друга, `BasicApi.Storage`, `Hubs/` | любой функции |
| Контроллеры, `ChatHub` | своей функции и общего; хаб — любых функций | репозиториев напрямую |
| Корень композиции: `Program.cs`, `Extensions/` | всего | — |

Разрешённые связи между функциями:
- **Messages → Media** (`IMediaService`): вложения сообщений — это файлы.
- **Sync → Chats, Folders, Users**: снимок состояния собирает все функции.
- **Config → Media, Groups, Push** (их `*Options`): клиенту лимиты нужны одним запросом.
- **Auth, Devices → `Hubs`** (`HubConnectionRegistry`): выход разрывает соединения.

Новая связь — осознанно: дописать сюда с причиной или вынести общее в `Services/`. В `Services/`
и `Models/` код попадает, только когда им пользуются хотя бы две функции.

## Путь запроса

```
HTTP → ForwardedHeaders → ExceptionHandlingMiddleware → заголовки безопасности → статика
     → CORS → аутентификация (JWT + живая сессия) → rate limiter → авторизация
     → контроллер → сервис функции → IChatPolicy → репозитории (IDbSession, одна транзакция)
                                   → IChatEventPublisher → outbox + журнал (та же транзакция)
OutboxDispatcher (фон) → SignalR-группы пользователей и чатов
                       → PushQueue → PushSender → WebPush
```

- **Контроллеры тонкие**: атрибуты, документация Swagger, ограничение параметров
  (`Math.Clamp`), вызов сервиса. Хаб — такой же адаптер над теми же сервисами.
- **Права — в одной точке**, `IChatPolicy`: членство, автор сообщения, роли и права в группах,
  блокировки, настройки приватности. Сервисы не проверяют членство сами.
- **Ошибки** — исключения-наследники `DomainException` с машиночитаемым кодом;
  `ExceptionHandlingMiddleware` превращает их в RFC 7807 ProblemDetails с `errorCode`, хаб —
  в `HubException` вида `"CODE: message"`. Справочник кодов — в
  [api-contract-changes.md](api-contract-changes.md#справочник-кодов-ошибок).
- **Транзакции**: `IDbSession` — одна сессия БД на запрос; репозитории делят её транзакцию.
  Изменение и его событие записываются вместе или не записываются вовсе.
- **Лимиты**: глобальный по пользователю (анонимный — по IP), отдельные политики `auth` и
  `commands`. IP клиента берётся из `X-Forwarded-For` только от доверенных прокси.

## События и синхронизация

- **Журнал на пользователя** (`user_updates`): каждое изменение, которое должен узнать
  пользователь, пишется с монотонным номером `pts`. Клиент после реконнекта вызывает
  `GET /api/sync?since={pts}`; если разрыв слишком большой — перезагружает состояние через
  `GET /api/sync/state`. Журнал хранится ограниченный срок (`JournalCleanup`).
- **SignalR — только быстрый канал** тех же записей, а не источник правды. Потерянное при
  обрыве событие клиент догоняет через `/sync`. Поэтому транспорт заменяем: меняется только
  адаптер `IChatEventPublisher`.
- **Outbox**: событие записывается в транзакции изменения и рассылается фоновым
  `OutboxDispatcher` — доставка «хотя бы один раз». «Печатает» и онлайн — эфемерные, уходят сразу
  и не журналируются.
- **Команды — через REST**, сокет доставляет события. Методы хаба `SendMessage` и `Typing`
  оставлены для совместимости и вызывают те же сервисы.
- **Полная история на новом устройстве**: `/sync/state` (чаты, папки, закрепы, архив, черновики,
  настройки, блокировки) + пагинация назад + медиа, пока они хранятся. Проверяется сквозным
  тестом `NewDeviceTests`.
- **Push**: только тем, у кого нет живого соединения; не отправителю, не заглушившим чат, не
  заблокировавшим отправителя. Очередь в памяти: потерянное при рестарте уведомление не стоит
  таблицы — само сообщение уже в журнале.
- **Веб-клиент** живёт по той же схеме: снимок, события хаба, догон журнала; применение событий —
  чистые идемпотентные функции, типы — из снимка OpenAPI. Подробности —
  [BasicWebClient/README.md](../BasicWebClient/README.md).

## Ключевые решения

**Модель сообщения.** `seq` (монотонный в чате), `client_message_id` (идемпотентность повторной
отправки), `type`, `text` + `entities` (разметка и упоминания смещениями, не markdown; сервер
проверяет смещения и схемы ссылок `http`/`https`/`mailto`), `reply_to_message_id`,
`forward_from_*`, `edited_at`, `deleted_at`. Удалённое для всех становится «надгробием»: текст и
вложения вычищаются.

**Статусы «отправлено / доставлено / прочитано».** Два указателя на участника —
`last_delivered_seq` и `last_read_seq`, без записи на каждое сообщение. «Доставлено» — хотя бы одно
устройство подтвердило `pts` через `POST /api/sync/ack`.

**Файлы отдельно от сообщений.** Загрузка по presigned URL в S3-совместимое хранилище, таблица
`attachments`; сообщения и аватары ссылаются на файл. Отсюда пересылка без повторной загрузки,
галерея и единые проверки. Файлы отдаются так, чтобы чужой контент не исполнялся на домене
приложения (`Content-Disposition`, `nosniff`, CSP `sandbox`). У файла есть `sha256` и состояние
хранения (`stored` / `expired`) — задел под политику хранения и P2P-передачу в будущем.

**Группы.** Роли `owner` / `admin` / `member`, набор прав на роль + переопределения на участника,
лимит участников (настройка), журнал действий для админов.

**Приватность.** Контактов нет, «свои» — участники общих чатов. Видимость онлайна (взаимная,
как в Telegram), кто пишет в личку, кто добавляет в группы; блокировки. Всё проверяет
`IChatPolicy`.

**Устройство = вход.** Устройство — семейство сессий за claim `sid`: появляется при входе, живо,
пока жива голова цепочки refresh-токенов. К нему привязана push-подписка. Выход, выход везде и
смена пароля удаляют устройства и рвут их соединения.

**E2E сознательно не делаем.** Оператор сервера — сама организация; основной клиент — веб,
который отдаёт тот же сервер; E2E отключило бы поиск, превью, push с текстом и историю на новом
устройстве. Логику, читающую текст сообщений, держим отключаемой как гигиену приватности.

**Деплой ручной.** CI (GitHub Actions) гоняет `scripts/test.ps1` и сборку образа на каждый push,
но не имеет ни секретов, ни доступа к серверу. Прод обновляется по [deploy.md](deploy.md).

## Как добавить функцию

1. Папка `Features/<Функция>/`: контроллер, сервис с интерфейсом, DTO запросов,
   `<Функция>Feature.cs` с `Add<Функция>Feature()`; вызов — в `ServiceExtensions.AddApiServices`.
2. Права — новым методом `IChatPolicy`, а не проверкой в сервисе.
3. Изменение, которое должны увидеть другие устройства, — через `IChatEventPublisher` в
   транзакции изменения; новый тип записи журнала — в `UpdateTypes`.
4. SQL — в репозитории `BasicApi.Storage`, схема — новой миграцией; изменённый SQL покрывается
   интеграционным тестом на Postgres.
5. Тесты — в `Features/<Функция>/` обоих тестовых проектов.
6. Контракт — только аддитивно; описание — в [api-contract-changes.md](api-contract-changes.md),
   снимок OpenAPI обновляется осознанно (`UPDATE_OPENAPI_SNAPSHOT=1`).
