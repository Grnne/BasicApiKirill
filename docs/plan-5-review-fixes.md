# План 5: исправления по ревью веб-клиента (клиент и сервер)

Ревью 2026-10-01: пять срезов клиента, находки перепроверены по коду. Где корень на сервере — чиним
и сервер. Один пункт — один коммит, баг сначала воспроизводится падающим тестом. Короткие проверки
по ходу (`test.ps1 -SkipIntegration` + затронутые интеграционные тесты), полный `test.ps1` и UI e2e —
один раз в конце.

## Серьёзные

**П1. Выход всегда завершает свою сессию.**
- Сервер: `POST /api/auth/logout` отзывает и сессию из access-токена (claim семейства), а не только
  ту, чей refresh-токен прислан. Сейчас клиент с истёкшим access-токеном получает 401, обновляет
  пару и повторяет выход со старым, уже заменённым токеном — сервер ничего не отзывает.
- Клиент: токен для выхода — свежий, из localStorage; хаб останавливается до запроса (иначе вместо
  выхода «Сеанс завершён»); «Выйти везде» отключает push только после успешного ответа.

**П2. Ссылки на файлы без бесконечного цикла.**
- Клиент: один id запрашивается не чаще раза в 30 с; ответ без новых ссылок не перерисовывает
  всё; ссылки, истёкшие за время простоя, обновляются сами; аватар после ошибки пробует новую
  ссылку.
- Сервер менять не нужно: аватар заблокировавшего уже скрыт и в участниках, и в поиске; цикл
  возникал на закешированном id после блокировки, на спешащих часах и на недоступном файле.

**П3. Правка сообщения не подменяется черновиком.** Режим выделения прячет поле ввода, а не
пересоздаёт его: правка и загрузки сохраняются.

## Средние

**П4. Диалоги группы закрываются вместе с чатом** (удалили группу, исключили из неё).

**П5. Папки: снятая галочка снимает и закреп.**

**П6. Синхронизация не встаёт.** Неудачный первый снимок повторяется с паузами; повтор, о котором
попросили во время запроса, не теряется; догон после событий — не позже 3 с даже при непрерывном
потоке; старый прогон после выхода не применяется к новому входу.

**П7. Превью `ChatListUpdated` работает.**
- Сервер: в превью есть `seq` (как в контракте), тип, действие и вложения.
- Клиент: превью двигает строку и последнее сообщение, счётчики остаются за догоном; полное
  сообщение с тем же `seq` заменяет превью.

**П8. Прочтение — только увиденного.** Загрузка ленты не ставит прочтение сама, это делает лента,
когда вкладка видна и прокручена вниз; неотправленная отметка отправляется снова.

**П9. Лента: прокрутка и даты.** При переходе в чат — к последним сообщениям; переход к дате до
первого сообщения не очищает чат; ошибка прошлого чата не переносится в новый.

**П10. Лента: гонки истории.** Страница, запрошенная до перехода, не вклеивается в новое окно;
события, пришедшие до первой страницы, не теряются; своё сообщение, отправленное из окна в середине
истории, не пропадает.

**П11. Статусы «в сети» после переподключения и для новых чатов.**

**П12. Вкладка не переключается на другого пользователя** при обновлении токена.

**П13. Спойлеры не видны без нажатия.**
- Сервер: скрытый текст замаскирован в цитате ответа, в превью `ChatListUpdated` и в push.
- Клиент: замаскирован в строке списка чатов; спойлер открывается с клавиатуры.

**П14. Сервер: страницы клиента по глубоким ссылкам (`/client/chat`) с `no-cache`.**

## Менее важные

**П15. Поле ввода.** Enter во время IME-набора не отправляет; «перестал печатать» уходит в свой
чат; ответ на сохранение черновика не возвращает отправленный текст; черновик при закрытии вкладки
уходит с `keepalive`; повторная пересылка после сетевой ошибки не дублирует.

**П16. Мелочи интерфейса.** Слишком большое фото — «слишком большое»; устройства обновляются после
смены пароля; меню чата открывается с начала; «Повторить» в галерее догружает, а не сбрасывает;
`push.refresh` без необработанной ошибки; при запрете на добавление в группу видно, кто запретил;
срок правки пересчитывается при открытии меню; восстановление сессии при старте повторяется при
сетевой ошибке, а не показывает форму входа.

**П17. Разбор текста.** Автоссылка сохраняет парную `)`; тип сущности проверяется как своё поле.

**П18. Телефон и доступность.** Меню сообщения не выходит за экран; у кнопок-иконок есть
`aria-label`; Escape и фокус в меню и диалогах; подтверждение удаления фокусирует «Отмена».

**П19. CSP режима разработки без `ws:`/`wss:` к любым хостам.**

**П20. Архитектура.** Текущий пользователь и выбранный чат — в `entities`, фичи не импортируют
модели друг друга.

**П21. Тесты.** Юнит-тесты на `http.ts`, `hub.store`, `safeRedirect`; e2e: push пропускается только
при отказе браузера, проверки доступа не принимают 400, проверки, которые не могут упасть, исправлены,
меню входящего сообщения на телефоне.
