# Чек-лист ручной проверки клиента

Проверка текущего веб-клиента (`BasicWebClient`) против развёрнутого стека: перед
деплоем — на локальном прод-стеке, после деплоя — на проде. Сокращённый вариант
для каждого деплоя — в [deploy.md](deploy.md), шаг 4; полный — после изменений
в авторизации, хабе, доставке событий и перед релизом.

Автоматические сквозные тесты (`scripts/e2e.ps1`) закрывают протокол; этот
чек-лист — то, что видит человек: клиент правильно понимает ответы и события.

## Подготовка

Нужны два пользователя (Алиса и Боб) и три независимых окна: Алиса в двух
«браузерах», Боб в третьем. Независимые — значит с раздельным `localStorage`:
разные браузеры, профили или приватное окно. Локально проще всего открыть клиент
с разных origin'ов — у каждого своё хранилище:

| Окно | Адрес |
|---|---|
| Алиса, браузер 1 | `http://127.0.0.1:18080/client/` |
| Алиса, браузер 2 | `http://127.0.0.1:18081/client/` |
| Боб | `http://localhost:18080/client/` |

Для этого API публикуется на loopback двумя портами (только для ручной проверки,
override-файл не коммитить):

```yaml
# docker-compose.manual.yml
services:
  basicapi:
    ports:
      - "127.0.0.1:18080:8080"
      - "127.0.0.1:18081:8080"
```

В `.env` для проверки — `JWT_EXPIRY_MINUTES=2`: так за пару минут видно, что
клиент переживает истечение access-токена (пункт 5.3).

Отметка «API» — клиент этого не умеет, проверяется запросом (Swagger в Development
или `curl`), и уже покрыто интеграционными и сквозными тестами.

## 1. Вход и сессии

| # | Действие | Ожидается |
|---|---|---|
| 1.1 | Регистрация Алисы и Боба | Сразу открывается страница чатов, статус «на связи» |

| # | Действие | Ожидается |
|---|---|---|
| 3.1 | Боб пишет Алисе (у Алисы чат закрыт) | У Алисы превью и счётчик непрочитанных «1» без F5; время — местное |
| 3.2 | Алиса открывает чат | Сообщение на месте, счётчик пропал |
| 3.3 | Алиса нажимает F5 | Счётчик не вернулся (прочитанность сохранена на сервере) |
| 3.4 | Алиса отвечает (у Боба чат открыт) | Ответ у Боба сразу; у Боба счётчик не растёт; своё сообщение у Алисы не считается непрочитанным |
| 3.5 | Боб пишет, Алиса открыта в двух браузерах | Сообщение приходит в оба |
| 3.6 | Отправка пустого сообщения или из одних пробелов | Не отправляется, ошибок в консоли нет |
| 3.7 | Длинная переписка (50+ сообщений), прокрутка вверх | Старые подгружаются без дублей и пропусков, позиция не прыгает |
| 3.8 | API: поиск по сообщениям `GET /api/chats/{id}/messages/search?q=запу` | Находит «запускаем» и «запуска» |
| 3.9 | API: переход к дате `GET /api/chats/{id}/messages/at?date=…` | Страница заканчивается последним сообщением на момент `date` |
| 3.10 | API: Боб правит своё сообщение, удаляет другое у всех, ставит реакцию, отвечает с разметкой (план 2, Ф1) | Клиент Алисы не падает и не пишет ошибок; после F5 — текст с правкой, удалённого нет, превью и счётчик пересчитаны; ответ виден обычным текстом |
| 3.11 | API: Алиса открывает «Избранное» (`POST /api/chats/saved`), затем пишет в него из клиента | После F5 чат в списке («Без названия» — клиент не знает тип `saved`), сообщения в него уходят |

## 5. Соединение

| # | Действие | Ожидается |
|---|---|---|
| 5.1 | Перезапуск API (`docker restart basicchat_api`) | Статус «переподключение», затем «на связи»; сообщения снова приходят без F5 |
| 5.2 | Сообщения, отправленные, пока окно было отключено | Видны после открытия чата |
| 5.3 | Подождать дольше срока access-токена (`JWT_EXPIRY_MINUTES`) | Соединение не рвётся, сообщения приходят; F5 не нужен |

## Известные проблемы клиента

Найдены этим чек-листом; фронт в плане 1 не трогаем, чинятся при доработке клиента
в [плане 2](plan-2-features.md#контракты).

- **Переподключение с истёкшим токеном.** Хаб берёт access-токен из памяти и
  обновляет его, только если токена нет совсем. Если соединение оборвалось (деплой,
  обрыв сети), а токен в памяти уже истёк — вкладка не делала REST-запросов дольше
  `JWT_EXPIRY_MINUTES`, — переподключение получает 401, после пяти попыток (~47 с)
  клиент сдаётся: «нет связи» до F5. Пункт 5.1 проходит, только если токен ещё жив.
- **После отказа нет повторных попыток.** Даже с живым токеном: если сервер недоступен
  дольше ~47 с, клиент остаётся в «нет связи» до F5.
- **Ошибка «логин занят»** показывается текстом сервера по-английски
  (`Username already exists`), остальные ошибки входа — по-русски.
- **Новые возможности плана 2 не поддержаны** — ожидаемо, пока фронт не доработан:
  правка, удаление и реакции видны только после F5 (клиент не слушает `MessageUpdated`,
  `MessageDeleted`, `ReactionsChanged`); разметка, ответы и пересылка показываются
  обычным текстом; «Избранное» — «Без названия».
