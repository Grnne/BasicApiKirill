# Чек-лист ручной проверки клиента

Проверка веб-клиента (`BasicWebClient`) против развёрнутого стека: перед деплоем — на локальном
прод-стеке, после деплоя — на проде. Сокращённый вариант для каждого деплоя — в
[deploy.md](deploy.md), шаг 4; полный — после изменений в авторизации, хабе, доставке событий и
перед релизом.

Автоматические сквозные тесты (`scripts/e2e.ps1`) закрывают протокол, тесты клиента (Vitest) —
применение событий и логику экранов; этот чек-лист — то, что видит человек.

## Подготовка

Нужны три пользователя (Алиса, Боб, Карл) и четыре независимых окна: Алиса в двух «браузерах»,
Боб и Карл — каждый в своём. Независимые — значит с раздельным `localStorage`: разные браузеры,
профили или приватное окно. Локально проще всего открыть клиент с разных origin'ов — у каждого
своё хранилище:

| Окно | Адрес |
|---|---|
| Алиса, браузер 1 | `http://127.0.0.1:18080/client/` |
| Алиса, браузер 2 | `http://127.0.0.1:18081/client/` |
| Боб | `http://localhost:18080/client/` |
| Карл | `http://carl.localhost:18080/client/` (браузер сам направляет `*.localhost` на loopback) |

API и хранилище файлов публикуются на loopback (только для ручной проверки, override-файл не
коммитить). Ссылки на файлы подписываются для адреса хранилища, а оно пускает загрузку только с
перечисленных origin'ов:

```yaml
# docker-compose.manual.yml
services:
  basicapi:
    ports:
      - "127.0.0.1:18080:8080"
      - "127.0.0.1:18081:8080"
    environment:
      Storage__PublicUrl: http://127.0.0.1:18333
  seaweedfs:
    ports:
      - "127.0.0.1:18333:8333"
    command: ["mini", "-dir=/data", "-webdav=false", "-admin.ui=false", "-s3.port.iceberg=0",
              "-s3.port.lance=0", "-master.telemetry=false",
              "-s3.externalUrl=http://127.0.0.1:18333",
              "-s3.allowedOrigins=http://127.0.0.1:18080,http://127.0.0.1:18081,http://localhost:18080,http://carl.localhost:18080"]
```

В `.env` для проверки — `JWT_EXPIRY_MINUTES=2`: так за пару минут видно, что клиент переживает
истечение access-токена (8.3). Для раздела 9 нужны VAPID-ключи (`PUSH_VAPID_PUBLIC_KEY`,
`PUSH_VAPID_PRIVATE_KEY`, см. `.env.prod.example`) и обычный браузер: push работает только в
безопасном контексте (`localhost`, `127.0.0.1` или HTTPS) и с разрешёнными уведомлениями.

## Известные проблемы клиента

Ошибок, найденных этим чек-листом, сейчас нет. Ограничения, о которых стоит знать:

- **Ограничение собеседника видно только после попытки написать.** Сервер не говорит заранее,
  что собеседник закрыл личные сообщения или заблокировал вас (иначе блокировку было бы видно):
  поле ввода сменяется объяснением после первого отказа.
- **Галерея карточки не обновляется вживую.** Файл, отправленный, пока карточка открыта,
  появится после переключения вкладки галереи.
- **Push проверяется в обычном браузере.** Встроенные браузеры инструментов (например, в
  приложении Claude) не регистрируют service worker и держат уведомления запрещёнными —
  раздел 9 там не пройти.
