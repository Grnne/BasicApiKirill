# План 1. Рефакторинг и отладка текущего

Цель: текущий функционал работает корректно и безопасно, а архитектура готова принять
функции из [плана 2](plan-2-features.md) без переделок. Новых пользовательских функций
здесь нет. Единственное исключение — синхронизация (`/sync`): без неё нельзя честно
починить доставку после реконнекта.

Номера `R*` и `A*` ссылаются на [backend-roadmap.md](backend-roadmap.md).

Оценки — на одного разработчика, грубо. Итого **~5–6 недель**.

## Правила выполнения

- Каждый пункт — отдельный PR или коммит.
- **CI нет до конца всей работы** (перенесён в последний этап [плана 2](plan-2-features.md)).
  До этого тесты гоняются вручную: перед каждым мёржем — полный прогон юнит- и
  интеграционных тестов скриптом из пункта 0.1, результат отмечается в описании PR
  или коммита.
- **Деплой ручной** — по инструкции из пункта 0.1.
- Каждый исправленный баг сначала воспроизводится тестом, который падает до правки.
- Любой изменённый SQL покрывается интеграционным тестом на реальном Postgres.
- Фронт не трогаем, но он должен продолжать работать. Контракт меняется только
  аддитивно: новые поля, эндпоинты и события добавляем, старые не ломаем. Каждое
  изменение — в [api-contract-changes.md](api-contract-changes.md).
- В конце каждого этапа — ручная проверка текущего клиента по чек-листу из этапа 3.

## Изменения схемы БД в этом плане

```
users         + username_normalized, email_normalized (уникальные); timestamptz
chats         + last_seq, private_key (уникальный для private); timestamptz
chat_members  + last_read_seq (вместо last_read_message_id); индекс (user_id); timestamptz
messages      + seq (уник. с chat_id), client_message_id (уник. с sender_id),
                search_vector (generated tsvector, GIN); timestamptz
user_updates    user_id, pts, type, payload jsonb, created_at      PK (user_id, pts)
user_sync_state user_id, device/session_id, acked_pts, updated_at
outbox          id, type, payload jsonb, created_at, processed_at
```

## Что изменится для фронта

Только добавления, старое работает:

- новые REST-команды отправки и typing (методы хаба остаются);
- `seq` и `clientMessageId` в `MessageDto`;
- `/api/sync/*`;
- коды ошибок в `HubException` вместо молчаливого игнорирования;
- исправленные счётчики непрочитанных и курсоры.
