⚡ ChatHub SignalR хаб

Подключение: wss://host/hubs/chat?access_token={jwt}
Аутентификация: JWT Bearer (передаётся в query string access_token)
← REST API · изменения контракта — docs/api-contract-changes.md
Хаб — канал событий. Команды (отправка сообщения, «печатает») есть и в REST: POST /api/chats/{chatId}/messages и POST /api/chats/{chatId}/typing. Методы хаба SendMessage и Typing работают через те же сервисы и остаются, пока клиенты не переедут на REST. Идемпотентная отправка (clientMessageId) — только в REST.

📤 Client → Server (вызываемые методы)

Client → Server JoinChat(chatId)
Подписаться на MessageCreated чата. Вызывается при открытии чата на клиенте. Не участник — ошибка NOT_A_MEMBER.
ПараметрТипОписание
chatIdGuidID чата
Подписка живёт на соединении: после реконнекта JoinChat нужно вызвать снова.
Client → Server LeaveChat(chatId)
Отписаться от событий чата. Вызывается при закрытии чата на клиенте.
ПараметрТипОписание
chatIdGuidID чата
Client → Server SendMessage(chatId, text)
Отправить сообщение. Пробелы по краям обрезаются, длина — 1–4096 символов. Лучше — POST /api/chats/{chatId}/messages с clientMessageId: повтор после обрыва сети не создаст дубль.
ПараметрТипОписание
chatIdGuidID чата
textstringТекст сообщения
События: MessageCreated (в группу чата — полное сообщение) и ChatListUpdated (каждому участнику, включая отправителя, — текст обрезан до 100 символов).
Ошибки: MESSAGE_EMPTY, MESSAGE_TOO_LONG, NOT_A_MEMBER, RATE_LIMITED.
Client → Server Typing(chatId, isTyping)
«Печатает». Остальным участникам чата приходит TypingChanged. Статус гаснет сам через 6 секунд: пока пользователь набирает текст, повторять true раз в несколько секунд; перестал — false. Не участник — NOT_A_MEMBER; вызовы сверх лимита молча отбрасываются.
ПараметрТипОписание
chatIdGuidID чата
isTypingbooleantrue — начал печатать, false — перестал

Ошибки методов

Ошибка метода приходит как HubException. SignalR добавляет к тексту свой префикс: "An unexpected error occurred invoking 'SendMessage' on the server. HubException: NOT_A_MEMBER: User is not a member of this chat". Код — слово сразу после HubException: .
КодКогда
NOT_A_MEMBERПользователь не участник чата
MESSAGE_EMPTYТекст пустой или из одних пробелов
MESSAGE_TOO_LONGДлиннее 4096 символов после обрезки пробелов
RATE_LIMITEDБольше 20 вызовов за 10 секунд на соединение

📥 Server → Client (подписка на события)

Доставка — «хотя бы один раз». MessageCreated, ChatListUpdated, MessageUpdated, MessageDeleted, ReactionsChanged, MessagesDelivered, MessagesRead, ReadStateChanged, DraftUpdated и ChatCreated сохраняются в той же транзакции, что и само изменение, и рассылаются из очереди: сбой сервера не теряет событие, но изредка оно может прийти дважды — сообщения различаются по id (или chatId + seq). Пропущенное, пока клиент был отключён, забирается через GET /api/sync?since={pts}. TypingChanged и UserOnlineChanged — эфемерные: не сохраняются и не повторяются.
Server → Client MessageCreated
Новое сообщение в чате. Получают соединения, подписанные на чат (JoinChat). Содержит полный текст.

MessageDto — тот же тип, что в истории (GET /api/chats/{chatId}/messages/cursor):

Клиент: добавить сообщение в ленту. Своё сообщение, отправленное через REST, узнаётся по clientMessageId — временную копию можно заменить без дубля.
Server → Client ChatListUpdated
Новое последнее сообщение чата. Получают все участники, включая отправителя (для его других устройств), даже если чат не открыт. Текст обрезан до 100 символов.
АргументТипОписание
chatIdGuidID чата
messageMessageDtoСообщение (текст ≤ 100 символов)
Клиент: обновить превью в списке чатов, НЕ добавлять в ленту. Чата нет в списке — взять его строку: GET /api/chats/{chatId}/item.
Server → Client MessageUpdated
Сообщение отредактировано (PATCH /api/chats/{chatId}/messages/{messageId}). Получают все участники на все соединения, не только открывшие чат.
АргументТипОписание
messageMessageDtoСообщение целиком, с новым text, entities и editedAt
Клиент: заменить сообщение по id; если это последнее сообщение чата — обновить превью в списке. ChatListUpdated на правку не приходит.
Server → Client MessageDeleted
Сообщение удалено (DELETE /api/chats/{chatId}/messages/{messageId}). Удалено у всех — получают все участники; удалено «у себя» — только устройства удалившего.
АргументТипОписание
deletedobjectchatId, messageId, seq, forEveryone
Клиент: убрать сообщение из ленты. Было последним в чате — перезапросить строку списка: GET /api/chats/{chatId}/item (там же пересчитанные непрочитанные).
Server → Client ReactionsChanged
Кто-то поставил, сменил или убрал реакцию (PUT/DELETE /api/chats/{chatId}/messages/{messageId}/reactions). Получают все участники на все соединения.
АргументТипОписание
reactionsobjectchatId, messageId, reactions — сводка после изменения, userId — кто изменил, emoji — его реакция теперь (null — убрал)
Клиент: заменить reactions сообщения; если userId свой — запомнить emoji как myReaction.
Server → Client MessagesDelivered
Устройство другого участника получило ваши сообщения и подтвердило это через POST /api/sync/ack. Приходит только авторам, чьи сообщения впервые стали доставленными; в группе решает первый получивший.
АргументТипОписание
receiptobjectchatId, userId — кто получил, seq — всё до этого номера включительно
Клиент: outboxDeliveredSeq = max(outboxDeliveredSeq, seq) и пересчитать статусы своих сообщений чата: seq ≤ outboxDeliveredSeq — delivered.
Server → Client MessagesRead
Другой участник прочитал ваши сообщения (POST /api/chats/{chatId}/read). Приходит только авторам, чьи сообщения впервые стали прочитанными.
АргументТипОписание
receiptobjectchatId, userId — кто прочитал, seq
Клиент: поднять до seq и outboxReadSeq, и outboxDeliveredSeq; свои сообщения с seq ≤ outboxReadSeq — read.
Server → Client ReadStateChanged
На одном из ваших устройств сдвинулся указатель прочтения или изменилась метка «непрочитано». Получают все ваши устройства.
АргументТипОписание
stateobjectchatId, lastReadSeq, unreadCount, unreadMentionCount, markedUnread
Клиент: заменить эти поля в строке чата.
Server → Client DraftUpdated
Черновик чата изменился на одном из ваших устройств или был отправлен. Получают все ваши устройства.
АргументТипОписание
draftobjectchatId, draft — { text, entities, replyToMessageId, updatedAt }; null — удалён или отправлен
Клиент: обновить черновик чата. Не перетирать поле ввода, в котором сейчас печатают, если updatedAt не новее своего последнего сохранения.
Server → Client ChatCreated

Server → Client UserOnlineChanged
Пользователь появился в сети или ушёл. Получают участники общих с ним чатов.
АргументТипОписание
userIdGuidID пользователя
isOnlinebooleantrue — в сети, false — нет
Событие — только о смене статуса. Снимок при подключении не приходит: после каждого подключения и реконнекта клиент сам берёт текущее состояние — POST /api/users/status с { "userIds": [...] } (до 200 id; тех, с кем нет общего чата, сервер из ответа убирает) или GET /api/users/{userId}/status. Офлайн отдаётся явно: isOnline: false.
Server → Client TypingChanged
Собеседник печатает или перестал. Получают остальные участники чата. Кто печатает прямо сейчас (например, сразу после подключения) — GET /api/users/typing.
АргументТипОписание
chatIdGuidID чата
userIdGuidID пользователя
isTypingbooleantrue — печатает, false — перестал
Если false не пришло (клиент собеседника упал), статус гаснет сам через 6 секунд — клиенту стоит держать тот же таймаут.

🔄 Соединение

Онлайн. Пользователь в сети, пока у него есть хотя бы одно соединение: первое соединение рассылает UserOnlineChanged(userId, true), закрытие последнего — false. Все устройства одного пользователя — один статус.
Токен и срок жизни соединения. Access-токен проверяется при подключении. Открытое соединение живёт, пока жив вход (сессия), с которого оно открыто, — истечение самого access-токена его не закрывает. Сервер закрывает соединение:
  • сразу — при POST /api/auth/logout (соединения этого входа) и POST /api/auth/logout-all (все соединения пользователя);
  • в течение минуты — если вход закончился иначе: цепочка refresh-токенов отозвана при повторном использовании токена или истекла.
Переподключаться — только со свежим access-токеном: если токен истёк, перед реконнектом сделать POST /api/auth/refresh. Refresh вернул 401 — вход закрыт, показать экран входа.
После реконнекта подписки на чаты потеряны, события за время разрыва не пришли. Порядок: JoinChat открытого чата → GET /api/sync?since={pts} (пропущенные сообщения и новые чаты; при snapshotRequired: true — перечитать GET /api/sync/state) → POST /api/users/status для статусов.
