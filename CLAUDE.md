# BasicChatApi

Бэкенд мессенджера: .NET 10, ASP.NET Core (REST + SignalR), Dapper, Postgres. Устройство
проекта, правила зависимостей и ключевые решения — [docs/architecture.md](docs/architecture.md).
Прочитать перед изменением структуры или добавлением функции.

## Команды

```powershell
./scripts/test.ps1                   # сборка, юнит- и интеграционные тесты, аудит пакетов (нужен Docker)
./scripts/test.ps1 -SkipIntegration  # быстро, без Docker
./scripts/test.ps1 -Image            # плюс сборка прод-образа
./scripts/e2e.ps1                    # сквозные тесты против развёрнутого стека
```

CI (`.github/workflows/ci.yml`) запускает тот же `scripts/test.ps1` на каждый push.

## Правила работы

- `BasicWebClient` (фронт) не трогаем.
- Перед каждым коммитом — `scripts/test.ps1`; строка-итог из конца вывода — в сообщение коммита.
- Один коммит — один пункт плана. Коммит и push — только по просьбе.
- Баг сначала воспроизводится тестом, который падает до правки.
- Изменённый SQL покрывается интеграционным тестом на реальном Postgres.
- Контракт API меняется только аддитивно; каждое изменение описывается в
  [docs/api-contract-changes.md](docs/api-contract-changes.md). Снимок OpenAPI
  (`BasicApi.IntegrationTests/Snapshots/openapi.json`) обновляется осознанно:
  `UPDATE_OPENAPI_SNAPSHOT=1`, дифф проверяется глазами.
- Код функции — в `Features/<Функция>/`, общее — в `Services/` и `Models/`, только если им
  пользуются хотя бы две функции. Namespace = папка. Тесты — по той же раскладке.

## Комментарии и документы

- Комментарии в коде — на английском и только о важном: неочевидные инварианты, конкуренция,
  безопасность, причины странных решений. Не пересказывать код, не ссылаться на пункты планов.
  Аннотация класса — одна-две строки.
- XML-документация ручек контроллеров и полей DTO — это описание API в Swagger, её поддерживаем.
- Документация и отчёты — на русском.

## Окружение разработчика

- Не трогать чужие Docker-контейнеры и том `chat_postgres_data`: интеграционные тесты поднимают
  свои контейнеры сами (Testcontainers).
- Перед тяжёлыми прогонами (нагрузочный, прод-стек локально) — проверить свободную память и
  спросить.
- Секреты и тестовые пароли не повторять в чате и не коммитить; `.env*`, кроме
  `.env.prod.example`, в git не попадают.
