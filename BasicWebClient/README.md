# BasicWebClient

Веб-клиент для BasicChatApi: Vue 3 (Composition API) + TypeScript + Vite + Pinia. Умеет всё, что
даёт бэкенд: личные чаты и группы с ролями и правами, «Избранное», закрепы, архив, mute, папки,
черновики, разметку, ответы, пересылку, правку и удаление, реакции, статусы доставки, поиск,
файлы и альбомы, аватары, профиль, приватность и блокировки, онлайн-статус и «печатает»,
устройства и push-уведомления, регистрацию — открытую или по приглашению (ссылка
`/client/login?invite=…`, «Пригласить» в настройках).

## Запуск

Нужен работающий бэкенд. Проще всего так:

```bash
docker compose up -d postgres seaweedfs
dotnet run --project ../BasicApi
```

`seaweedfs` — хранилище файлов; без него всё работает, кроме файлов и аватаров.

Затем в этой папке:

```bash
npm install
npm run dev
```

Клиент поднимется на `http://localhost:5173` и будет проксировать `/api` и
`/hubs` на бэкенд, а `/media` — в хранилище файлов. Адреса задаются в `.env`
(см. `.env.example`). API подписывает ссылки на файлы для адреса Vite
(`Storage__PublicUrl=http://localhost:5173` в профилях `launchSettings.json`) — как в
проде, где хранилище отдаёт Caddy с того же домена.

Прокси — не только про удобство: в разработке фронт и API оказываются на одном
origin, как и в проде. Значит нет CORS, нет cross-site cookie и нет расхождения
между «как работает у меня» и «как работает на сервере».

## Команды

| Команда         | Что делает                                        |
| --------------- | ------------------------------------------------- |
| `npm run dev`   | Дев-сервер с горячей перезагрузкой                |
| `npm run check` | Проверка типов (`vue-tsc --noEmit`)               |
| `npm test`      | Тесты (Vitest)                                    |
| `npm run test:watch` | Тесты в режиме наблюдения                    |
| `npm run gen:api` | Типы REST и событий хаба из снимка OpenAPI → `src/shared/api/schema.d.ts` |
| `npm run build` | Проверка типов + сборка в `../BasicApi/wwwroot/client` |
| `npm run preview` | Локальный просмотр собранной версии             |
| `npx playwright test` | Сквозные тесты интерфейса против развёрнутого стека (`E2E_BASE_URL`); удобнее через `../scripts/e2e-ui.ps1` |

Сквозные тесты интерфейса лежат в `e2e/`: каждый сценарий — как у живых людей, в отдельных
браузерах, с регистрацией своих пользователей через API. Страница, на которой случилась ошибка
JavaScript или нарушение CSP, валит тест, даже если все проверки прошли. Запускаются против
локального прод-стека (`docs/deploy.md`) в установленном Edge или Chrome.

Типы ответов и событий не пишутся руками: они генерируются из снимка OpenAPI сервера
(`BasicApi.IntegrationTests/Snapshots/openapi.json`). Тест падает, пока сгенерированные типы
отстают от снимка.

## Структура

Слоистая раскладка (упрощённый feature-sliced). Правило одно:
**импортировать можно только вниз**.

```
src/
  app/        точка входа, роутер, реакция на конец сеанса и клики по уведомлениям
  pages/      экраны: LoginPage, ChatPage, SettingsPage; общий выход из аккаунта
  features/   действия: auth, chat-list, chat-info, devices, groups, messages, message-search,
              privacy, profile, push, user-search, realtime
  entities/   данные предметной области: chat, message, media, user, config
  shared/     инфраструктура: http, hub (SignalR), ui-кирпичики, утилиты
  testing/    сборщики тестовых данных для Vitest
public/sw.js  service worker уведомлений (копируется в сборку как есть)
```

- `pages` собирают фичи вместе — только здесь фичи встречаются друг с другом;
- фича **не импортирует модель другой фичи**. Если состояние нужно двоим —
  его место в `entities` (так получилось с участниками чата, ссылками на файлы и тем, кто
  вошёл, — `entities/user/model/session.store`);
- `shared` не знает ни о фичах, ни о страницах.

Эти правила и запрет `v-html` проверяет тест `src/app/architecture.test.ts`.

Внутри фичи: `api/` — запросы, `model/` — стор, `lib/` — чистые функции, `ui/` — компоненты.
Тесты — рядом с кодом (`*.test.ts`).

## Как клиент держит данные свежими

- **Снимок, события, журнал.** На входе клиент берёт снимок `/api/sync/state` (чаты, папки,
  профиль, приватность, блокировки), затем применяет события хаба по мере прихода. После
  переподключения, возврата на вкладку и через секунду после живых событий он догоняет журнал
  `/api/sync?since=pts` и подтверждает прочитанное `POST /api/sync/ack`. Если журнал не догнать
  (`snapshotRequired`), клиент берёт снимок заново. Хаб — только быстрый канал: потерянное
  событие придёт из журнала.
- **Применение — чистые функции** (`entities/*/model/*.ts`) без Vue и сети. Одно событие может
  прийти дважды (вживую и из журнала), поэтому каждое либо заменяет то, что трогает, либо
  защищено: последнее сообщение двигается только вперёд по `seq`, счётчик непрочитанного растёт
  только за `seq` выше учтённого. Повтор и порядок покрыты тестами.
- **Отправка — через REST** с `clientMessageId`: повтор после обрыва не создаёт второе
  сообщение. Сетевые ошибки и 5xx повторяются сами, короткий 429 — переждать один раз; отказ
  показывается с причиной и кнопкой «Повторить».
- **Файлы** грузятся в три шага: заявка, `PUT` по подписанной ссылке прямо в хранилище,
  подтверждение. Ссылки на показ кешируются до близкого истечения и запрашиваются пачками.

## Как устроена авторизация

- **access-токен живёт только в памяти** (Pinia), никуда не сохраняется;
- **refresh-токен** — в `localStorage`, иначе перезагрузка страницы требовала бы
  пароль. Плата за это — XSS: скрипт на странице сможет его прочитать. Поэтому в
  приложении нет ни одного `v-html`, ссылки из сообщений — только `http`, `https` и `mailto`,
  а CSP запрещает скриптам ходить на чужие адреса: в деве — `<meta>` в `index.html`, в
  сборке — заголовок от API (тег из сборки убирается, см. `devOnlyCsp` в `vite.config.ts`);
- при 401 HTTP-клиент **один раз** обновляет пару токенов и повторяет запрос. Все
  обновления — одно общее, а между вкладками — по очереди под `navigator.locks`, с токеном,
  прочитанным заново: сервер считает повторное использование refresh-токена кражей и
  обрывает все сессии пользователя;
- refresh-токен ротируется на каждом обновлении — сохраняется всегда новый;
- **сеанс, закрытый в другом месте** (выход с другого устройства, «выйти везде», смена пароля):
  сервер обрывает соединение хаба, а клиент перед переподключением проверяет сеанс обновлением
  токена. Отказ — сторы очищаются, страница уходит на вход с «Сеанс завершён».

Сторы не импортируют друг друга ради токена: `http` и `hub` берут его через
`AuthBridge` (см. `shared/api/http.ts`), который регистрируется один раз в
`app/main.ts`.

## Уведомления

`public/sw.js` — обычный JavaScript без плагинов сборки: показывает уведомление о новом
сообщении или реакции на своё (в нём нет токена — всё нужное приходит в самом push) и по клику
открывает чат. Открытый клиент, когда его вкладка не на экране, просит его же показать такое
уведомление (`postMessage`), так что вид один (`features/push/model/notifier.store.ts`: ещё звук —
включён, пока его не выключат в настройках, — и счётчик непрочитанных в заголовке вкладки).

Уведомления включены по умолчанию: разрешение браузер спрашивает при первом клике после входа;
«Выключить» в настройках запоминается на устройстве. После входа подписка этого браузера
переходит к вошедшему, при выходе — снимается. Работает в безопасном контексте (`localhost` или
HTTPS); push при закрытой вкладке — только если на сервере заданы VAPID-ключи.

## Прод

`npm run build` кладёт результат в `../BasicApi/wwwroot/client`, откуда его
раздаёт Kestrel: `/` редиректит на `/client/`, а `MapFallbackToFile` отдаёт
`index.html` на внутренние маршруты вроде `/client/chat`. Файлы из `assets/` кешируются
навсегда (в имени хеш), `index.html` и `sw.js` — перепроверяются каждый раз.

В образе то же самое делает отдельная стадия `client` в `BasicApi/Dockerfile` —
node нужен только для сборки и в финальный образ не попадает. Снаружи стоит Caddy: TLS и
файлы из хранилища с того же домена ([docs/deploy.md](../docs/deploy.md)).

## Панель событий

В режиме разработки справа висит журнал событий хаба — он сильно помогает
понять, что именно прислал сервер. В прод-сборку не попадает: компонент
подключается динамически под `import.meta.env.DEV`.
